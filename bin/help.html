Hydroscope Manual

Model and observsational data

Error metrics and statistics are compared between model and observation data. To load model or observational data click the button beside the "File:" label. You can load a .csv or .nc file. The file must have a time or date index. This means for a csv file the first column must contain proper dates or times. For a netcdf file one of the dimensions must be time. There can be lots of other columns or variables.

Variable

After loading files you must select the variable you are interested in. The variables founds are in the "Variable:" dropdown box.

Aggregation

If the model and observation data are at different timescales then aggregation can be performed (if you are have selected Aggregation in the Settings) to enable better statistics calculation. Moreover all the figures and tables produced are produced at coarser timescales, eg if your data is daily, you will also get monthly, seasonal, and yearly plots. This dropdown box allows you to set what resampling method to use. Likely you want 'mean', except for rain/precip where you probably want 'sum'.

Dimensions

For a NetCDF file variables can have more than just a time dimension. You must select the dimension using the Dimensions button. A csv file cannot contain dimensions (currently the only dimension is time in the first column), so you don't have to click the Dimensions button. Selecting Dimensions can be a bit fiddly because a dimension might have a lot of possible values. If there are only a few possible values, they are listed in a dropdown box, so you can just select them. If there are a lot of values, then you are going to have to type one in, so you will have to know your data before using this tool.

Time range

You can optionally restrict the time range of a model or observational variable by clicking the Time Range button and modifying the start and end times.

View

The View button shows a summary of your selected NetCDF or csv file.

Plot

The Plot button can only be used after selecting your File, Variable, and possibly Dimensions. The presented graphics are simplistic, this is not a plotting program, and the plot button is just for you to confirm that you have selected your correct Variable/Dimensions.

Purpose

Here you can select the purpose of your model, which will then in turn determine the metrics that will be calculated. Pushing the Calculate button will generate plots and metrics.

Results

Output that results from Calculating a purpose will appear here. Generally there will be some figure tabs first, then at least one tabular data with a row per metric that makes sense for this purpose.

Settings

The File -> Settings menu allows you set parameters that some of the metrics need and whether time aggregation is allowed.
  • Peaks: For high flow modelling you are interested in the peak flows. This parameter determines how many peaks will be identified in your model and obersation hydrographs.
  • Peak gap: The minimum number of days between peak flow events.
  • BFI alpha: The alpha parameter in the Lyne and Hollick baseflow index filter for low flow modeling.
  • BFI passes: The number of passes for in the Lyne and Hollick baseflow index filter for low flow modeling.
  • Last month of year: This is to define seasonal and annual aggregation.
  • Aggregation: If selected then model and observational data do not have to have the same timestep, the finer timescale will be aggregated to the coarser.

Updating

Upon startup, github is checked to see if there is a newer version available, if so, you are prompted to see if you want this new version. It might take a few minutes to download and the install started.

Optionally you can go to Help -> Upgrade and will be presented with:

  • Version of the currently running program
  • Version of the code on github, this will likely be at least as new as your running program
  • A list of installable versions found on github. These will likely include some older versions and something close to the code version on github, but might be a bit older because an installable version does not have to be generated everytime the code is updated on github
You can click on an installable version, and after some time, the download will start and the install started.
